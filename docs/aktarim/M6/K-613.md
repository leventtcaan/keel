# K-613 · Projeksiyonun sayıları: kapılar, üç senaryo, aralık, yalnız ileri — ADR-052

> Durum: **aktarılmadı**. Motor hesaplar, `GET /v1/projection` sunar, telefon çizer (K-606). Sorular 95-96.

## Projede nerede
| # | Basamak | Proje yeri |
|---|---|---|
| 1 | Plana oturmuş başlangıç: glikojen, sıvı, AT o alımın dengesinde; ağırlık verilen kilo | `EnergyBalanceModel.weightsKg(start, settledOnKcal, …)` |
| 2 | Kapılar sırasıyla: yaş → güvenlik ağı → 28 gün → bu hafta tartı → en az 100 kcal yön → BMI 20 (kayıp) → modelin ulaştığı beden | `ShapeProjection.of` |
| 3 | Senaryo = günlerin %p'si plan, kalanı bakım; model 26 hafta | `Run.scenario` |
| 4 | Aralık: bakım ±1 MJ iki koşu + 2,5 kg taban; ters uç bugünde durur | `Run.scenario` |
| 5 | Güvensiz senaryo yok: haftalık tavan (min(1 kg, %1)), BMI 18,5 | `fasterThanTheCap`, `PROJECTION_MIN_BMI` |
| 6 | Uç: rıza, plan yoksa TOO_EARLY, bekleyen güvenlik kararı da SAFETY_HOLD | `DecisionService.projection` |

## Neden böyle
ADR-052: gün payı söylenebilir bir davranış; ±%15 bakım hatası aralığı anlamsızlaştırırdı, Hall'un ±1 MJ'si bu modelin kendi belirsizliği.
BMI ondalıkta okunur (64,8/1,8² kayan noktada 19,999…). Bakıma 100 kcal'den yakın plan modelin kendi hatası içinde "değişmez".

## Kanıt
RED motor 3 + 12 + API 4 (CI). İnceleme: (95) 1 kcal açıkta hiç değişmeyen senaryo + özellik testinin aktivite uyumsuzluğu (rastgele kırmızı) →
`projection_min_gap_kcal` + üreteç düzeltmesi; (92) bakım alt sınırında yuvarlama → 500 → `ceil + 1`; (80) bekleyen sert durdurma →
SAFETY_HOLD. Test analizi (45 mutant, 15 yaşıyordu): aralığın değerleri, haftalık tavanın iki kolu (özellik), BMI 18,5 ile 20 ayrımı, 18 yaş,
bulk eşitliği, kapı sırası testleri eklendi; iki gerçek hata (Jackson ≤0 → 500 → `OUTSIDE_MODEL`; BMI kayan noktası) düzeltildi. Kendi
mutasyonum 4/4; özellik testleri 3 koşuda kararlı. 400 rastgele cut'ta %90 gösterilir, aralık tipik ±3,3 kg; istek başına ~5,5 ms.
